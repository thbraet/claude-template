## Formatting Overview

- **Output format:** CSV
- **Split strategy:** Kaggle-provided train/test split; stratified 5-fold CV for internal validation during modeling (per 1.3)

## Formatting Transformations

### Type Casting

No explicit type casts were needed — all numeric fields were already correctly typed as int64/float64 from tasks 3.2–3.3.

### Column Operations

| # | Operation | Fields | Details |
|---|-----------|--------|---------|
| 1 | Drop | Name, Ticket, Cabin | Raw engineering sources already consumed by Title, TicketGroupSize, HasCabin, Deck |
| 2 | Reorder | All | ID → Target → Numeric features → One-hot features |

### Encoding

| # | Field | Original Values | Encoding | Method | Reference Category (Dropped) |
|---|-------|----------------|----------|--------|------------------------------|
| 1 | Title | Mr, Mrs, Miss, Master | One-hot | pd.get_dummies | Mr (most frequent, male baseline) |
| 2 | Deck | A, B, C, D, E, F, G, T, Unknown | One-hot | pd.get_dummies | Unknown (77% of passengers) |

**Column alignment:** Deck_T exists only in train (1 passenger); added to test as zeros to ensure identical schemas.

## Train / Validation / Test Split

### Split Strategy

- **Method:** Kaggle-provided split (not random — fixed by competition)
- **Validation:** Stratified 5-fold cross-validation on training set during Phase 4 (no separate validation file)
- **Rationale:** This is a single historical event, not time series. The Kaggle split is canonical. Validation via CV avoids further reducing the small training set (891 rows).

### Split Statistics

| Metric | Train | Test |
|--------|-------|------|
| Records | 891 | 418 |
| PassengerId range | 1–891 | 892–1309 |
| Features | 26 | 26 |
| Target (Survived) | Present | Absent (predict) |
| Survived=0 (Deceased) | 549 (61.6%) | — |
| Survived=1 (Survived) | 342 (38.4%) | — |
| Class ratio (0:1) | 1.61:1 | — |

### Distribution Shift Check

KS tests from 2.4 confirmed no significant distributional differences between train and test for Pclass, Age, SibSp, Parch, Fare, Sex. Minor Embarked shift (p<0.05) is low risk given Embarked's weak predictive power (Cramer's V=0.172).

## Output Dataset Specification

### Final Schema

| # | Field | Type | Role | Description |
|---|-------|------|------|-------------|
| 1 | PassengerId | int64 | ID | Unique passenger identifier |
| 2 | Survived | int64 | Target | 0=deceased, 1=survived (train only) |
| 3 | Pclass | int64 | Feature | Ticket class (1/2/3) |
| 4 | Sex | int64 | Feature | Binary (0=male, 1=female) |
| 5 | Age | float64 | Feature | Age in years (imputed where missing) |
| 6 | Fare | float64 | Feature | Ticket fare in GBP |
| 7 | FareLog | float64 | Feature | log(Fare + 1) |
| 8 | SibSp | int64 | Feature | Siblings/spouses aboard |
| 9 | Parch | int64 | Feature | Parents/children aboard |
| 10 | FamilySize | int64 | Feature | SibSp + Parch + 1 |
| 11 | FamilySizeBin | int64 | Feature | 0=Small(1), 1=Medium(2-4), 2=Large(5+) |
| 12 | IsAlone | int64 | Feature | 1 if FamilySize==1 |
| 13 | HasCabin | int64 | Feature | 1 if cabin number recorded |
| 14 | TicketGroupSize | int64 | Feature | Passengers sharing same ticket |
| 15 | AgeMissing | int64 | Feature | 1 if Age was imputed |
| 16–22 | Deck_A through Deck_T | int64 | Feature | One-hot deck indicators (ref: Unknown) |
| 23–24 | Embarked_Q, Embarked_S | int64 | Feature | One-hot embarkation (ref: Cherbourg) |
| 25–27 | Title_Master, Title_Miss, Title_Mrs | int64 | Feature | One-hot title (ref: Mr) |

## Assumptions & Business Validation

### Assumptions Made

| ID | Assumption | Category | Rationale | Status |
|----|-----------|----------|-----------|--------|
| A3.5-1 | Dropping Name, Ticket, and Cabin loses no modeling signal beyond what Title, TicketGroupSize, HasCabin, and Deck already capture | Feature Scope | All engineering from these fields was completed in 3.3; raw text adds no further value for scikit-learn models | Pending verification |
| A3.5-2 | One-hot encoding with reference category dropping (Mr for Title, Unknown for Deck) is appropriate for all planned model families | Encoding | Tree models are invariant to reference category; logistic regression benefits from interpretable reference levels | Pending verification |
| A3.5-3 | No separate validation file is needed — stratified 5-fold CV during modeling is sufficient | Splitting | Per 1.3 evaluation methodology; avoids further reducing the small 891-row training set | Pending verification |
| A3.5-4 | CSV is an adequate output format (vs. Parquet) for this dataset size | Infrastructure | Total data <1 MB; Parquet overhead not justified; scikit-learn reads CSV and arrays equally well | Pending verification |
| A3.5-5 | Adding Deck_T as zeros to test (absent in test set) is safe and does not introduce bias | Schema Alignment | Deck_T has only 1 observation in train; the model will learn near-zero weight for this feature regardless | Pending verification |
