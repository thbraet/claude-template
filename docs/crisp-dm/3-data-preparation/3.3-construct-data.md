## Construction Overview

## Feature Catalog

### Domain-Specific Features

| # | Feature Name | Formula / Logic | Source Fields | Domain Rule | Rationale |
|---|-------------|----------------|---------------|-------------|-----------|
| 1 | Title | Regex extraction from Name, mapped to 4 groups (Mr, Mrs, Miss, Master) | Name | Title reflects sex, age, marital status — all factors in evacuation priority | 15.7%-79.2% survival range across title groups |
| 2 | HasCabin | 1 if Cabin is not NaN, else 0 | Cabin | Cabin assignment correlates with 1st/2nd class — proxy for socio-economic status | 66.7% vs 30.0% survival |
| 3 | Deck | First character of Cabin; 'Unknown' if missing | Cabin | Deck position (A-G) influenced proximity to lifeboats | Decks B/D/E show ~75% survival |

### Aggregation Features

| # | Feature Name | Formula / Logic | Source Fields | Aggregation Level | Rationale |
|---|-------------|----------------|---------------|-------------------|-----------|
| 1 | FamilySize | SibSp + Parch + 1 | SibSp, Parch | Per passenger | Intermediate feature for FamilySizeBin |
| 2 | FamilySizeBin | Small (1), Medium (2-4), Large (5+) | FamilySize | Per passenger | Inverted-U survival pattern: Small ~30%, Medium ~58%, Large ~12% |
| 3 | IsAlone | 1 if FamilySize == 1, else 0 | FamilySize | Per passenger | 30.4% vs 50.6% survival; simpler binary alternative |
| 4 | TicketGroupSize | Count of passengers sharing the same Ticket number | Ticket | Per ticket (combined train+test) | Mirrors family size pattern; shared tickets indicate travel groups |

### Transformation Features

| # | Feature Name | Formula / Logic | Source Fields | Rationale |
|---|-------------|----------------|---------------|-----------|
| 1 | FareLog | log(Fare + 1) | Fare | Reduces extreme right skew from 4.78 to ~0.4 |

| 2 | FamilySize / FamilySizeBin / IsAlone | None — derived from SibSp, Parch (pre-event) | Safe | — |

| 4 | FareLog | None — fare paid at booking (pre-event) | Safe | — |
| 5 | TicketGroupSize | Low — computed on combined train+test | Safe | Ticket purchase is pre-event; group size is a static fact about the ticket, not derived from survival outcomes |
| 6 | Encoding (Sex, Embarked, FamilySizeBin) | None — deterministic mappings, no parameters fit on data | Safe | — |

**No data leakage detected.** All features represent pre-event passenger attributes. No feature uses future information or the target variable.

## Assumptions & Business Validation

### Assumptions Made

| ID | Assumption | Category | Rationale | Status |
|----|-----------|----------|-----------|--------|
| A3.3-1 | Title extraction with 4-group mapping (Mr, Mrs, Miss, Master) captures the key survival signal from Name | Feature Design | EDA showed 15.7%-79.2% survival range across these 4 groups; rare titles (<10 each) too sparse for separate categories | Pending verification |
| A3.3-2 | FamilySizeBin with 3 levels (Small/Medium/Large at cutpoints 1/4) captures the inverted-U pattern | Feature Design | EDA showed clear survival tiers: Size 1 ~30%, 2-4 ~58%, 5+ ~12% | Pending verification |
| A3.3-3 | TicketGroupSize computed on combined train+test is not data leakage | Methodology | Ticket purchase is a pre-event fact; group size is an immutable property of the ticket regardless of survival outcome | Pending verification |
| A3.3-4 | HasCabin (binary) is more useful than multi-level Deck for most models | Feature Design | 77% of Deck values are 'Unknown'; HasCabin captures the primary signal (66.7% vs 30.0% survival) | Pending verification |
| A3.3-5 | log(Fare+1) is preferred over other Fare transformations (sqrt, Box-Cox) | Feature Design | Reduces skew from 4.78 to ~0.4; simple, interpretable, handles Fare=0 without issues | Pending verification |
| A3.3-6 | Embarked one-hot with drop_first=True (dropping C=Cherbourg) is appropriate | Encoding | Avoids dummy variable trap; tree models are unaffected by reference category choice | Pending verification |
| A3.3-7 | Sex x Pclass interaction term is deferred to modeling phase rather than constructed here | Scope | Tree-based models capture interactions natively; explicit interaction terms only needed for logistic regression during model building | Pending verification |
