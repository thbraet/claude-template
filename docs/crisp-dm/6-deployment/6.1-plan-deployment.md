## Serving Architecture

### Serving Pattern
**Batch (one-time)** — Generate predictions for all 418 test passengers in a single batch run, export as CSV, and submit to Kaggle.

**Rationale:** This is a Kaggle competition submission, not a production service. There are no real-time, streaming, or recurring prediction requirements. A single batch run produces the final deliverable.

### Inference Pipeline

```
test.csv → Cleaning → Feature Engineering → XGBoost Predict → Format CSV → Kaggle Submit
```

| Stage | Component | Technology | Description |
|-------|-----------|------------|-------------|
| Ingestion | Load test data | pandas | Read `data/raw/titanic/test.csv` (418 rows) |
| Preprocessing | `src/cleaning.py` | pandas | Apply `clean_dataset()` with train-fitted parameters (title-group median ages, mode Embarked) |
| Feature Engineering | `src/features.py` | pandas | Apply `build_features()` — Title, FamilySize, IsAlone, Deck, etc. |
| Formatting | Format pipeline | pandas | Apply same encoding/scaling as `data/processed/train_formatted.csv` pipeline |
| Prediction | XGBoost model | xgboost / sklearn | Load trained model from MLflow, predict on formatted test features |
| Post-processing | Format submission | pandas | Create DataFrame with `PassengerId` and `Survived` (int 0/1) columns |
| Delivery | Export CSV | pandas | Write `submissions/submission_xgboost.csv` |

### Compute Infrastructure
| Resource | Specification | Purpose |
|----------|--------------|---------|
| Local workstation | macOS (Darwin 24.6.0), CPU | Run inference pipeline |
| Storage | Local filesystem | Store submission CSV (<10 KB) |

### Data Flow
1. Raw test data (`data/raw/titanic/test.csv`) is read — **never modified**
2. Cleaning and feature engineering produce `data/processed/test_clean.csv` and `data/processed/test_features.csv` (already generated in Phase 3)
3. Formatting produces `data/processed/test_formatted.csv` (already generated in Phase 3)
4. XGBoost model (loaded from MLflow) predicts survival probabilities
5. Predictions are thresholded at 0.5, cast to int, and paired with `PassengerId`
6. Final CSV is written to `submissions/submission_xgboost.csv`
7. CSV is manually uploaded to Kaggle

### Scaling Strategy
**N/A** — One-time batch prediction on 418 rows. Execution time is <1 second on local hardware. No scaling required.

## Rollout Strategy

### Approach
**Big-bang (single submission)** — Submit all 418 predictions to Kaggle in one batch.

**Rationale:** Kaggle evaluates the full test set at once. There is no partial submission or phased rollout option. The submission is instantly scored and reversible (new submissions replace previous ones).

### Rollout Phases

| Phase | Scope | Duration | Entry Criteria | Exit Criteria |
|-------|-------|----------|---------------|---------------|
| 1 - Generate predictions | 418 test passengers | <1 minute | Trained XGBoost model available in MLflow | Submission CSV passes validation checks |
| 2 - Submit to Kaggle | Full test set | <5 minutes | Valid submission CSV (418 rows, 2 columns, no nulls) | Kaggle accepts submission and returns score |
| 3 - Evaluate score | — | <1 day | Kaggle score returned | Score > 80% (BSC2) confirmed |

### Validation Gates
| Gate | Metric | Threshold | Measured Over |
|------|--------|-----------|--------------|
| Submission shape | Row count | Exactly 418 rows | Submission CSV |
| Submission columns | Column names | `PassengerId`, `Survived` only | Submission CSV |
| No missing values | Null count | 0 nulls | Submission CSV |
| Value range | Survived values | All values in {0, 1} | Submission CSV |
| PassengerId completeness | ID match | All 418 test IDs present, no duplicates | Submission CSV vs. test.csv |
| Kaggle accuracy | Test accuracy | > 80% (BSC2); minimum > 78% (BSC1) | Kaggle leaderboard |

### Rollback Triggers
| Trigger | Condition | Action | Owner |
|---------|-----------|--------|-------|
| Submission rejected | Kaggle returns format error | Fix CSV format, re-validate, resubmit | Thibauld |
| Accuracy < 78% | Kaggle score below gender baseline threshold | Investigate OOF-to-test gap; submit RF predictions as fallback (4.4 recommendation) | Thibauld |
| Accuracy 78-80% | Kaggle score below competitive threshold but above baseline | Assess whether to iterate (5.3 Q5.3-1); try voting ensemble (XGBoost + RF + LR) | Thibauld |

### Rollback Procedure
1. **Identify issue** — Check Kaggle score against thresholds (>80% target, >78% minimum)
2. **Diagnose** — Compare Kaggle score to OOF accuracy (84.73%); if gap >4%, investigate data pipeline for train/test inconsistencies
3. **Fallback submission** — Generate predictions using Random Forest (runner-up, 84.62% OOF) and submit
4. **Ensemble fallback** — If RF also underperforms, build simple voting ensemble (XGBoost + RF + LR) as documented in 4.4
5. **Notify** — Update project documentation with actual Kaggle scores and any deviations from expected performance
