## Executive Summary

### Business Problem
Colruyt Group's data science team needed a methodology benchmark — a complete, documented machine learning pipeline applied to a well-understood problem. The Kaggle Titanic competition (predicting which passengers survived the 1912 sinking) was chosen as the vehicle: a binary classification task with a fixed dataset, an objective external scoring mechanism, and a well-known baseline to beat.

### What We Did
We followed the full CRISP-DM methodology across six phases over two days. Starting from raw passenger data (891 labeled training records, 418 unlabeled test records), we profiled the data, identified key patterns (gender and passenger class as dominant survival factors), engineered features (extracting titles from names, computing family sizes, creating cabin indicators), and trained four families of machine learning models. The best model — a gradient-boosted tree ensemble (XGBoost) — was selected after systematic comparison against a gender-only baseline and three alternative model families.

### Key Results
| Outcome | Value |
|---------|-------|
| Prediction accuracy (cross-validated) | 84.73% — correctly classifying ~354 of 418 test passengers |
| Improvement over gender-only baseline | +7.69 percentage points (~25 additional correct predictions) |
| Most predictive features | Sex, passenger class, title (Mr/Mrs/Miss/Master), family size |
| Models evaluated | 5 techniques, 9 configurations (1 baseline + 4 default + 4 tuned) |
| Experiments tracked | 9/9 runs fully logged in MLflow |

### Business Impact
The primary value of this project is methodological, not operational. It delivers a complete, reusable CRISP-DM reference implementation with documented decisions at every step — from business understanding through deployment. The pipeline code (`src/cleaning.py`, `src/features.py`) is modular and can be adapted to future classification projects. The Kaggle leaderboard score provides an objective, external validation of the approach.

### Deployment Status
Ready for Kaggle submission. The XGBoost model predictions for all 418 test passengers have been generated and validated. Submission is pending manual upload to Kaggle.

### Key Risks and Limitations
- The 85% stretch accuracy target was not reached (84.73% — 0.27% short), though all minimum criteria are met
- The model struggles with "ambiguous passengers" (18.3% of cases where survival signals conflict, e.g., 3rd-class females, 1st-class males)
- Kaggle test accuracy has not yet been confirmed — the 84.73% is a cross-validated estimate with a 4.7% margin above the 80% threshold
- The formal feature ablation study (quantifying per-feature accuracy contribution) was not completed

### Recommended Next Steps
1. Submit XGBoost predictions to Kaggle and confirm test accuracy > 80%
2. If Kaggle accuracy < 80%, submit Random Forest or voting ensemble as fallback
3. Schedule Bart Mollet's methodology review of CRISP-DM documentation
4. Complete the project retrospective (6.4) to capture lessons for future projects

## Technical Report

### Methodology
This project followed the CRISP-DM methodology across 6 phases:

| Phase | Status | Key Outcome |
|-------|--------|-------------|
| 1. Business Understanding | Complete | Defined binary classification objective with two-tier accuracy thresholds (78%/80%); identified 4 business questions |

| 3. Data Preparation | Complete | Imputed missing values (title-group medians for Age); engineered 8 features (Title, FamilySize, HasCabin, etc.); produced 26-feature modeling dataset |
| 4. Modeling | Complete | Evaluated 5 techniques (Gender baseline, Logistic Regression, Random Forest, XGBoost, SVM); XGBoost selected as champion at 84.73% OOF accuracy |
| 5. Evaluation | Complete | All minimum success criteria met; process review confirmed strong methodology; decision: deploy |
| 6. Deployment | In Progress | Deployment plan and monitoring plan complete; final report (this document) and project review pending |

### Data Summary

#### Sources
| Source | Records | Date Range | Key Variables |
|--------|---------|-----------|---------------|
| train.csv (Kaggle) | 891 | April 15, 1912 (single event) | PassengerId, Survived (target), Pclass, Name, Sex, Age, SibSp, Parch, Ticket, Fare, Cabin, Embarked |
| test.csv (Kaggle) | 418 | April 15, 1912 | Same as above minus Survived |
| gender_submission.csv | 418 | — | Baseline predictions (females survive) |

#### Quality
- **Completeness:** Age ~20% missing (both sets); Cabin ~77% missing (both sets); Embarked 2 missing (train); Fare 1 missing (test)
- **Key issues found:** Age missingness is MAR (correlates with class, sex, title); Cabin missingness is MNAR (strongly stratified by class: 1st 18.5% vs 3rd 97.6%)
- **Remediation applied:** Age imputed via title-group medians (Mr: 30, Mrs: 35, Miss: 21, Master: 3.5); Embarked imputed with mode ('S'); Fare imputed with Pclass-conditional median (8.05); AgeMissing indicator added; Cabin converted to HasCabin binary + Deck extraction

### Feature Engineering
| Feature | Description | Source | Rationale |
|---------|-------------|--------|-----------|
| Title | Extracted from Name, mapped to 4 groups (Mr/Mrs/Miss/Master) | Name | Captures sex + age + social status; 15.7%–79.2% survival range |
| FamilySize | SibSp + Parch + 1 | SibSp, Parch | Intermediate for FamilySizeBin |
| FamilySizeBin | Small (1), Medium (2-4), Large (5+) | FamilySize | Inverted-U survival pattern: ~30%, ~58%, ~12% |
| IsAlone | 1 if FamilySize == 1 | FamilySize | 30.4% vs 50.6% survival |
| HasCabin | 1 if Cabin recorded | Cabin | 66.7% vs 30.0% survival; proxy for class |
| Deck | First character of Cabin; Unknown if missing | Cabin | Decks B/D/E show ~75% survival |
| FareLog | log(Fare + 1) | Fare | Reduces extreme right skew from 4.78 to ~0.4 |
| TicketGroupSize | Count of passengers sharing same ticket | Ticket | Mirrors family size pattern |
| AgeMissing | 1 if Age was imputed | Age | Missing Age → 29.4% survival vs 40.6% |

### Modeling Results

#### Models Evaluated
| Model | Accuracy (OOF) | vs. Baseline | F1 | ROC-AUC | Selected |
|-------|----------------|-------------|-----|---------|----------|
| Gender Baseline | 0.7868 ± 0.0188 | — | 0.709 | N/A | No |
| Logistic Regression (tuned, C=0.5) | 0.8283 ± 0.0214 | +5.27% | 0.775 | 0.875 | No |
| Random Forest (tuned, depth=8) | 0.8462 ± 0.0217 | +7.55% | 0.787 | 0.879 | Runner-up |
| **XGBoost (tuned)** | **0.8473 ± 0.0169** | **+7.69%** | **0.791** | **0.890** | **Yes** |
| SVM RBF (tuned, C=10) | 0.8283 ± 0.0167 | +5.27% | 0.781 | 0.866 | No |

#### Selected Model
- **Technique:** XGBoost (gradient boosted trees)
- **Primary Metric:** Accuracy = 84.73% (5-fold stratified CV)
- **Key Hyperparameters:** `n_estimators=100`, `max_depth=6`, `learning_rate=0.05`, `subsample=0.7`, `colsample_bytree=0.7`
- **Training Data:** 891 passengers (April 15, 1912), 26 features after engineering
- **MLflow Run ID:** `xgboost-tuned-20260331`

#### Error Analysis Summary
- **Best performing segments:** 1st/2nd-class females (near-certain survival correctly predicted); 3rd-class males (low survival correctly predicted)
- **Worst performing segments:** 3rd-class females (50% survival — coin flip), 1st-class males (37% survival — conflicting signals)
- **Systematic biases:** FN-biased (85 missed survivors vs 51 false survivors); model is more conservative than optimistic. 18.3% of passengers cause model disagreement across all 5 techniques — these "ambiguous passengers" represent the practical accuracy ceiling.

### Deployment Architecture
One-time batch prediction: test data flows through the same preprocessing pipeline (`src/cleaning.py` → `src/features.py` → formatting) as training data, XGBoost generates predictions, and the output is a Kaggle submission CSV (418 rows: PassengerId, Survived). Manual upload to Kaggle. No API, service, or infrastructure required. See [6.1](6.1-plan-deployment.md) for full details.

### Monitoring Plan
Not applicable for this one-time Kaggle submission. An educational monitoring plan documenting what would be monitored in a production setting (data drift via KS/Chi-squared tests, prediction distribution shifts, accuracy degradation triggers, quarterly retraining) is provided in [6.2](6.2-plan-monitoring.md).

### Recommendations for Future Iterations
1. **Simple voting ensemble** — XGBoost (84.73%) and RF (84.62%) are nearly tied; a majority vote of XGBoost + RF + LR could gain 0.5–1% accuracy
2. **Fare-per-person feature** — Passengers sharing tickets split the fare; dividing by TicketGroupSize may improve the fare signal
3. **Phase-gate stakeholder reviews** — Review assumptions and results at each phase transition rather than accumulating to the end
4. **Fairness assessment as standard practice** — Add subgroup performance checks (by gender, class, age) to the CRISP-DM template
5. **Input validation in reusable modules** — Add column presence and type assertions to `src/cleaning.py` and `src/features.py`

### Intended Use
- **Primary use case:** Predict binary survival (0/1) for 418 Kaggle test-set passengers from the Titanic competition
- **Intended users:** Thibauld (data scientist) for Kaggle submission; data science team for methodology reference
- **Out-of-scope uses:** Do not use for real-world survival prediction, risk assessment, insurance decisions, or any context involving living persons. This is a historical classification exercise on a public dataset.

### Training Data
- **Sources:** Kaggle Titanic `train.csv`
- **Date range:** Single historical event (April 15, 1912)
- **Size:** 891 rows × 26 features (after engineering and formatting)
- **Preprocessing:** Title-group median age imputation (fit on train only), mode imputation for Embarked, one-hot encoding for Title/Deck/Embarked, feature engineering (FamilySize, HasCabin, FareLog, etc.)

### Evaluation Data
- **Validation set:** 5-fold stratified CV on 891 training rows (~178 per fold, preserving 38.4% survival rate)
- **Test set:** 418 Kaggle test passengers (ground truth unavailable locally; scored by Kaggle)
- **Splitting strategy:** Stratified 5-fold CV with `random_state=42`; no separate hold-out (dataset too small)

### Fairness Assessment
| Subgroup | Accuracy (OOF) | vs. Overall | Acceptable |
|----------|---------------|-------------|-----------|
| Female, 1st class | Very high (~97%) | +12% | Yes |
| Female, 2nd class | Very high (~92%) | +7% | Yes |
| Female, 3rd class | Moderate (~70%) | -15% | Yes — reflects genuine ambiguity (50% historical survival rate) |
| Male, 1st class | Moderate (~75%) | -10% | Yes — reflects conflicting signals (37% historical survival) |
| Male, 2nd class | High (~85%) | +0% | Yes |
| Male, 3rd class | High (~88%) | +3% | Yes — large segment, low survival (13.5%) is well-predicted |
| Children (0-12) | Good (~80%) | -5% | Yes — small sample; "children first" captured but some 3rd-class boys missed |
| Alone passengers | Moderate (~78%) | -7% | Yes — lower survival rate (30.4%) creates more FN opportunities |

Note: Subgroup accuracy is approximate, based on out-of-fold error analysis from 4.4. A formal fairness assessment with protected-group definitions was not performed, as this is a historical dataset with no modern protected attributes.

### Limitations
- **Ambiguous passengers:** 18.3% of passengers have conflicting survival signals (e.g., 3rd-class female, 1st-class male with large family); model accuracy drops to ~70% for these cases
- **Small dataset:** 891 training rows limits model complexity and statistical power; XGBoost shows ~7% train-validation gap despite regularization
- **Missing data:** Age (20%) and Cabin (77%) required imputation/engineering; imputed values are approximations that add noise
- **Static dataset:** No ability to collect additional features or update the model — the Kaggle dataset is fixed
- **No calibration:** Predicted probabilities were not formally calibrated; binary predictions (0/1) are reliable but probability estimates should not be treated as precise

### Ethical Considerations
- **Potential harms:** Minimal — this is a historical dataset (1912) with no living subjects. All passengers are deceased. No modern protected groups are affected by predictions.
- **Mitigations:** The model is used solely for a Kaggle competition and methodology reference. No real-world decisions are made based on its predictions.
- **Human oversight:** All predictions are reviewed by Thibauld before submission. No automated decision-making.

### Recommendations
- **Use this model for:** Kaggle Titanic competition submission; methodology reference for future classification projects
- **Do not use this model for:** Any real-world prediction, risk assessment, or decision-making involving living persons
- **Monitor:** Check Kaggle leaderboard score after submission; compare to OOF estimate (84.73%); see [6.2](6.2-plan-monitoring.md)
