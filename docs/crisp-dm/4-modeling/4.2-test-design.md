## Data Splitting Strategy

### Approach: Fixed Kaggle Split + Stratified 5-Fold Cross-Validation

**Rationale:** The Kaggle competition provides a fixed train/test split. With only 891 training rows, creating a separate validation hold-out would further reduce an already small training set. Stratified 5-fold CV on the full training set provides robust validation estimates while maximizing data usage. This is not a time series problem, so random stratified splits are appropriate.

### Split Definition

| Set | Criteria | Records | Proportion | Purpose |
|-----|----------|---------|------------|---------|
| Training | PassengerId 1–891 (Kaggle-provided) | 891 | 68.1% | Model fitting via 5-fold CV |
| Test | PassengerId 892–1309 (Kaggle-provided) | 418 | 31.9% | Final unbiased evaluation (Kaggle submission) |

### Cross-Validation Design

- **Strategy:** Stratified 5-fold CV on all 891 training rows
- **Number of folds:** 5
- **Fold sizes:** ~713 train / ~178 validation per fold
- **Stratification:** Preserves ~38.4% survival rate in each fold
- **Shuffle:** Yes, with `random_state=42` for reproducibility

### Data Leakage Prevention

| Risk | Mitigation |
|------|-----------|
| Preprocessing leakage | All imputers/encoders fit on train only in tasks 3.2–3.5 |
| CV-internal leakage | StandardScaler fit inside each CV fold via `Pipeline` (for LR, SVM) |
| Group leakage | N/A — each passenger is unique, no repeated entities |
| Temporal leakage | N/A — single historical event, no temporal dimension |
| Target leakage | All features are pre-event passenger attributes; no post-event information (verified in 2.3) |
| Train/test overlap | PassengerId ranges disjoint: 1–891 vs 892–1309 (verified in notebook) |

## Evaluation Metrics

### Primary Metric

| Attribute | Value |
|-----------|-------|
| **Name** | Accuracy |
| **Formula** | (TP + TN) / (TP + TN + FP + FN) |
| **Why chosen** | Kaggle's sole evaluation metric; direct 1:1 mapping to business success criteria BSC1/BSC2 |
| **Success threshold** | ≥ 85% CV (target), ≥ 80% CV (minimum) |
| **Aggregation** | Overall (per submission) |
| **Implementation** | `sklearn.metrics.accuracy_score` |

### Secondary Metrics

| Metric | Formula | Why Included | Threshold |
|--------|---------|-------------|-----------|
| F1-score | 2·(P·R)/(P+R) | Balances precision/recall for 38.4% minority class | — |
| ROC-AUC | Area under ROC curve | Discrimination ability, threshold-independent | — |
| Precision | TP / (TP + FP) | Understand false positive rate (false survivors) | — |
| Recall | TP / (TP + FN) | Understand false negative rate (missed survivors) | — |
| CV std | std(fold accuracies) | Stability of performance across folds | < 3% |

### Business Translation

| Technical Metric | Business Meaning | Example |
|-----------------|-----------------|---------|
| Accuracy of 85% | ~355 of 418 test passengers correctly classified | ~36 more correct than gender baseline (320) |
| Each 1% accuracy gain | ~4 more correct predictions out of 418 | Marginal value decreases as accuracy approaches ceiling |
| CV std < 3% | Model performance is stable, not dependent on specific data splits | Ensures reliability of the accuracy estimate |

## Baseline Definition

| Attribute | Value |
|-----------|-------|
| **Technique** | Gender-only model — predicts all females survive, all males perish |
| **Kaggle performance** | 76.5% accuracy (76.555% exact) |
| **CV performance** | ~78.7% accuracy on training set (validated in notebook) |
| **Minimum improvement** | ≥ 3.5% CV accuracy over baseline to justify model complexity |
| **Target improvement** | ~6.3% CV accuracy over baseline to reach 85% target |
| **Justification** | Kaggle-provided benchmark; captures the dominant predictor (Sex: Cramer's V=0.541); simple enough to be a floor, not a ceiling |

### Experiment Comparison

- Models are compared on **CV validation metrics** during development
- The **Kaggle test set** is used only for final selected model(s) — max 10 submissions/day
- All comparisons must include the gender baseline run as reference
- A model must exceed baseline by ≥ 3.5% CV accuracy to justify its complexity
