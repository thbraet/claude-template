# 4.1 Modeling Technique Selection

> **Project:** Titanic Survival Prediction
> **Date:** 2026-03-31
> **CRISP-DM Phase:** 4. Modeling
> **Status:** Draft

---

## Problem Summary

- **Problem Type:** Binary classification
- **Target Variable:** `Survived` (0 = deceased, 1 = survived)
- **Prediction Granularity:** Per passenger (one prediction per PassengerId)
- **Forecast Horizon:** N/A — historical event, no temporal forecasting
- **Primary Success Metric:** Kaggle test accuracy > 78% (minimum) / > 80% (target)
- **Secondary Metrics:** CV accuracy > 80% mean, CV std < 3%, feature importance consistency across methods

---

## Data Characteristics Affecting Technique Selection

| Characteristic | Finding (from EDA) | Impact on Technique Choice |
|---|---|---|
| Distribution of target | 61.6% deceased / 38.4% survived — moderate imbalance | Stratified CV required; resampling not needed; `class_weight='balanced'` for SVM |
| Feature interactions | Sex × Pclass spans 13.5%–96.8% survival | Tree models preferred (capture natively); logistic regression needs explicit interaction terms |
| Non-linear effects | Age: inverted-U for children; FamilySize: inverted-U at 2-4 | Tree models handle natively; linear models need binned features (already prepared) |
| Missing data | Age ~20% (MAR, imputed), Cabin ~77% (MNAR, encoded as HasCabin/Deck) | All handled in data preparation; no technique-level concern |
| Feature count | 25 features (after one-hot encoding) | Moderate — no dimensionality reduction needed |
| Sample size | 891 training rows, 342 minority class events | Small — overfitting risk real; EPP ~13.7 (sufficient for logistic regression); ensemble methods preferred |
| Multicollinearity | SibSp–FamilySize (r=0.89), Pclass–HasCabin (r=-0.73), Fare–FareLog (r=0.98) | Logistic regression needs L2 regularization; tree models robust |
| Scale differences | Fare range 512 vs. binary features range 1 | Logistic regression and SVM require StandardScaler; trees unaffected |

## Candidate Techniques

### Technique 1: Gender Baseline (Naive Baseline)
- **Family:** Rule-based / naive
- **Why considered:** Every model must beat this to be useful; Kaggle-provided benchmark
- **Assumptions:** Females survive, males perish
- **Assumption check:** Met — captures the dominant predictor (Sex: Cramer's V=0.541)
- **Strengths:** Dead simple; no overfitting; 76.5% accuracy
- **Weaknesses:** Ignores all other features; cannot exceed ~78.7% (train accuracy)
- **Interpretability:** High
- **Computational cost:** Negligible
- **Implementation complexity:** Negligible

### Technique 2: Logistic Regression (L2 Regularized)
- **Family:** Generalized linear model
- **Why considered:** Interpretable coefficients for DM1 (feature importance); strong baseline for classification; fast to train and tune
- **Assumptions:** Linear log-odds relationship; no severe multicollinearity; sufficient EPP
- **Assumption check:** Partially met — linearity holds after binning; multicollinearity present but manageable with L2; EPP ~13.7 is sufficient
- **Strengths:** Coefficients directly interpretable; probability outputs; fast; low overfitting risk
- **Weaknesses:** Cannot capture Sex×Pclass interaction natively; non-linear effects need explicit feature engineering
- **Interpretability:** High
- **Computational cost:** Low
- **Implementation complexity:** Low

### Technique 3: Random Forest
- **Family:** Bagged ensemble of decision trees
- **Why considered:** Handles feature interactions natively; built-in Gini/permutation importance for DM1; good bias-variance tradeoff for small datasets
- **Assumptions:** Sufficient samples per leaf; informative features exist
- **Assumption check:** Met — depth analysis shows overfitting starts at depth 6-8, controllable via hyperparameters
- **Strengths:** Captures Sex×Pclass natively; robust to outliers and multicollinearity; no scaling needed; parallel training
- **Weaknesses:** Can overfit with deep trees on 891 rows; less interpretable than logistic regression
- **Interpretability:** Medium
- **Computational cost:** Low
- **Implementation complexity:** Low

### Technique 4: XGBoost
- **Family:** Gradient boosted trees
- **Why considered:** State-of-the-art for tabular data competitions; strong regularization options; SHAP support for interpretability
- **Assumptions:** Similar to Random Forest; benefits from regularization tuning
- **Assumption check:** Met — small dataset is handled well with conservative hyperparameters (low learning rate, shallow trees)
- **Strengths:** Best expected performance; L1/L2 regularization; handles interactions and non-linearities; SHAP for post-hoc interpretability
- **Weaknesses:** More hyperparameters to tune; risk of overfitting with aggressive settings; external dependency
- **Interpretability:** Medium (via SHAP/gain importance)
- **Computational cost:** Low
- **Implementation complexity:** Low

### Technique 5: SVM (RBF Kernel)
- **Family:** Support vector machines (margin-based)
- **Why considered:** Completes 4-family comparison requirement (DM3); different modeling paradigm; works well on small datasets
- **Assumptions:** Feature scaling required; reasonable dimensionality (n_features << n_samples)
- **Assumption check:** Met — 891 samples / 25 features = 35.6x ratio; scaling via StandardScaler
- **Strengths:** Effective on small datasets; RBF kernel captures non-linear boundaries; `class_weight='balanced'` for imbalance
- **Weaknesses:** No native feature importance; less interpretable; requires scaling pipeline
- **Interpretability:** Low
- **Computational cost:** Low
- **Implementation complexity:** Medium

## Modeling Assumptions & Requirements

### Gender Baseline
- **Preprocessing required:** None — uses Sex column directly
- **Key hyperparameters:** None
- **Known limitations:** Ceiling ~78.7% (train accuracy); ignores all features except Sex
- **Fallback plan:** N/A — this is the floor, not a candidate for improvement

### Logistic Regression (L2)
- **Preprocessing required:** StandardScaler on all features
- **Key hyperparameters:** `C` (inverse regularization strength, search range: 0.01–100), `solver` (lbfgs), `penalty` (l2)
- **Known limitations:** Cannot capture Sex×Pclass interaction natively; non-linear Age/FamilySize effects partially addressed by binned features
- **Fallback plan:** If underfitting, add explicit interaction terms (Sex×Pclass) or try ElasticNet penalty

### Random Forest
- **Preprocessing required:** None (tree-based)
- **Key hyperparameters:** `n_estimators` (100–500), `max_depth` (3–10), `min_samples_leaf` (3–20), `max_features` (sqrt, log2, 0.3–0.8)
- **Known limitations:** High variance with small data; can overfit with deep trees
- **Fallback plan:** Increase `min_samples_leaf` or reduce `max_depth`; if still poor, prefer XGBoost

### XGBoost
- **Preprocessing required:** None (tree-based; handles missing values natively though data is already imputed)
- **Key hyperparameters:** `n_estimators` (100–500), `max_depth` (3–8), `learning_rate` (0.01–0.3), `subsample` (0.6–1.0), `colsample_bytree` (0.6–1.0), `reg_alpha` (0–1), `reg_lambda` (0–10)
- **Known limitations:** More hyperparameters to tune; risk of overfitting with aggressive settings
- **Fallback plan:** Lower learning rate + increase n_estimators; if underfitting, increase max_depth

### SVM (RBF)
- **Preprocessing required:** StandardScaler on all features
- **Key hyperparameters:** `C` (0.1–100), `gamma` (scale, auto, 0.001–1), `class_weight` (balanced)
- **Known limitations:** No native feature importance; less interpretable; requires probability calibration for probability outputs
- **Fallback plan:** Try polynomial kernel; if all SVM variants underperform, deprioritize in favor of tree models

## Techniques Considered but Not Selected

| Technique | Reason for Exclusion |
|---|---|
| Neural Networks / Deep Learning | Dataset too small (891 rows); no advantage over tree ensembles for tabular data of this size |
| K-Nearest Neighbors | No native feature importance; less competitive than ensembles; sensitive to irrelevant features and scale |
| Naive Bayes | Assumes feature independence — violated by strong multicollinearity (SibSp/FamilySize r=0.89, Pclass/HasCabin r=-0.73) |
| LightGBM | Very similar to XGBoost; one gradient boosting implementation is sufficient for this dataset size |
