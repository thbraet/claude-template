**Phase Assessment:** Data preparation was rigorous with strong leakage prevention. The data staging strategy (raw -> clean -> features -> formatted) with immutable raw data is textbook CRISP-DM. All 8 features proposed in Phase 2 were implemented.

**Key Decisions:**
- **Title-group median imputation for Age:** Strong domain-informed choice. Titles (Mr/Mrs/Miss/Master) are excellent proxies for age groups, yielding more accurate imputation than global median. Held up well.
- **HasCabin binary instead of complex Cabin imputation:** Pragmatic — with 77% missing, any imputation would be mostly noise. The binary flag captures the available signal (cabin recording correlates with class/survival). Correct decision.
- **FamilySizeBin cutpoints (1/4):** Domain-informed — solo travelers had lowest survival, groups of 2-4 highest, 5+ lowest again. Matched the inverted-U pattern from 2.3.
- **One-hot encoding with reference categories:** Appropriate for the model families used. Reference categories (Mr, Unknown deck, Cherbourg) were sensibly chosen.

## Methodology Assessment

### What Worked Well

1. **Baseline-first approach:** Establishing the gender baseline (78.7%) before any ML model set clear expectations and made all subsequent improvements interpretable. Every model comparison referenced this baseline.
2. **EDA-to-feature-engineering pipeline:** All 8 feature hypotheses from Phase 2 exploration were implemented in Phase 3. This tight coupling between understanding and preparation is exactly how CRISP-DM should work.
3. **Fit-on-train-only discipline:** Imputation parameters, encoders, and scalers were consistently fit on training data only, preventing data leakage. This was enforced architecturally through `compute_imputation_params()` in `src/cleaning.py`.
4. **Modular code in src/:** Reusable `cleaning.py` and `features.py` modules with pure functions (DataFrame in -> DataFrame out) made the pipeline reproducible and testable. Notebooks call these modules rather than duplicating logic.
5. **Comprehensive experiment tracking:** All 9 MLflow runs (1 baseline + 4 default + 4 tuned) logged with parameters, metrics, and artifacts. Full reproducibility.
6. **Error analysis depth (4.4):** The "ambiguous passengers" analysis (18.3% disagreement zone, 69.9% accuracy) provided genuine insight into the accuracy ceiling and why further gains are difficult.
7. **Transparent documentation:** Every decision across 18 documents includes rationale. Assumptions are explicitly stated with IDs. Business questions trace from 1.1 through to 5.1.

### What Should Be Improved

1. **Stakeholder engagement timing:** No formal stakeholder review occurred until Phase 5. For a real project, phase-gate reviews with the business would catch misalignment earlier. Bart Mollet's review is still pending.
2. **Assumption verification cadence:** Assumptions were documented thoroughly but none were formally verified during the project. A phase-gate verification process would prevent assumptions from accumulating.
3. **Input validation in src/ modules:** `cleaning.py` and `features.py` have no defensive checks for required columns or data types. While this works for a controlled pipeline, production code should validate inputs at module boundaries.
4. **Feature ablation study deferred:** DM4 was defined as a goal but not completed. While scoped as nice-to-have, completing it would have strengthened the feature engineering narrative and provided quantitative evidence for BQ4.

## Lessons Learned

### For This Project

1. **The 18.3% ambiguous passenger ceiling is real.** The error analysis in 4.4 shows that passengers with conflicting survival signals (3rd-class females, 1st-class males with families) set a practical floor on errors. Deployment (Kaggle submission) should set expectations at ~83-85%, not higher.
2. **Title extraction was the highest-value feature.** It appears in top-5 importance across multiple methods and serves as a proxy for both gender and social status. For the final report, highlight Title as the single most impactful engineered feature.
3. **The OOF-to-Kaggle gap is the primary uncertainty.** All success criteria pass on OOF estimates, but 2 of 4 BSC criteria require Kaggle confirmation. The 4.7% margin above 80% should absorb this gap, but it remains the key risk.
4. **Sign-offs should not be deferred to the end.** Having all 18 documents pending sign-off at Phase 5 creates a review bottleneck. For the remaining phases (5.3, 6.x), aim for incremental sign-off.

### For Future Projects

1. **Phase-gate reviews catch drift early.** A quick stakeholder check at each phase transition (even 15 minutes) prevents assumptions from compounding. This project's assumptions accumulated without verification across 4 phases.
2. **The baseline-first pattern is non-negotiable.** The gender baseline gave every subsequent model comparison a meaningful reference point. Future projects should always start with the simplest defensible model.
3. **EDA hypotheses should be numbered and tracked.** This project informally proposed 8 features from EDA and implemented all 8 — but the mapping was implicit. Future projects should maintain an explicit hypothesis -> feature -> validation registry.
4. **Add fairness assessment to the methodology template.** Even for learning projects, checking model performance across subgroups (by gender, class, age) is good practice and builds the habit for production projects where it is mandatory.
5. **Input validation in reusable modules pays off.** The `src/` modules work perfectly in this controlled pipeline but would break silently with unexpected inputs. Adding column/type assertions takes minutes and prevents hours of debugging.
