## Data Mining Problem Specification

- **Problem Type:** Binary classification
- **Target Variable(s):** `Survived` (0 = deceased, 1 = survived)
- **Prediction Granularity:** Per passenger (one prediction per PassengerId)
- **Prediction Horizon:** N/A — historical event, no temporal forecasting
- **Model Output Format:** Class label (0 or 1); secondary: predicted probability for threshold tuning
- **Intended Use of Output:** Kaggle submission CSV (`PassengerId`, `Survived`); methodology reference
- **Interpretability Requirement:** Hybrid — black box acceptable for leaderboard score, but feature importance analysis required for business question BQ1

### Input Feature Categories
| Category | Examples | Source |
|----------|----------|--------|
| Demographics | Sex, Age | train.csv |
| Socio-economic | Pclass, Fare, Cabin | train.csv |
| Family structure | SibSp, Parch | train.csv |
| Travel details | Embarked, Ticket | train.csv |
| Engineered | Title (from Name), FamilySize, IsAlone, Deck (from Cabin), FareBin, AgeBin | Derived from train.csv |

### Modeling Assumptions
- The training set (891 passengers) and test set (418 passengers) are drawn from the same underlying population and share the same feature distributions
- Survival patterns in the training data generalize to the test set without concept drift (single historical event)
- Missing data (Age, Cabin, Embarked) is not missing completely at random — missingness itself may carry signal
- Feature interactions (e.g., Sex × Pclass) are likely important given historical accounts of "women and children first" policies varying by class
- The small dataset favors models with strong regularization or inherent bias-variance tradeoff (tree ensembles, logistic regression) over deep learning

## Data Mining Goals

### Objective-to-Goal Traceability

| # | Business Objective (from 1.1) | Data Mining Goal | Problem Type | Output |
|---|-------------------------------|------------------|--------------|--------|
| 1 | BQ1: Identify which passenger characteristics are most predictive of survival | DM1: Rank features by predictive importance using permutation importance and/or model-intrinsic feature importances | Feature importance analysis | Ranked feature list with importance scores |
| 2 | BQ2: Outperform gender-only baseline (~76.5%) | DM2: Train a binary classifier achieving >78% accuracy (minimum) / >80% (target) on Kaggle test set | Binary classification | Class labels (0/1) |
| 3 | BQ3: Determine achievable accuracy ceiling | DM3: Systematically evaluate multiple model families and feature sets to characterize the accuracy frontier | Model comparison | Accuracy distribution across model families |
| 4 | BQ4: Identify highest-value feature engineering techniques | DM4: Measure incremental accuracy gain from each engineered feature via ablation study | Feature ablation | Per-feature accuracy delta |

### Goal Details

#### Goal DM1: Feature Importance Analysis
- **Business Objective:** BQ1 — What passenger characteristics are most predictive of survival?
- **Technical Description:** After training the best-performing model, compute feature importances using at least two methods (model-intrinsic + permutation importance). Identify the top-5 features and validate their direction of effect against historical domain knowledge.
- **Target Variable:** `Survived`
- **Key Predictors:** Sex, Pclass, Age, Fare, FamilySize (hypothesized top-5)
- **Output Format:** Ranked list with importance scores and direction of effect

#### Goal DM2: Binary Classification Model
- **Business Objective:** BQ2 — Outperform gender baseline
- **Technical Description:** Train and tune a binary classifier on the 891-row training set. Evaluate via stratified k-fold cross-validation. Generate predictions for all 418 test passengers. Submit to Kaggle for accuracy scoring.
- **Target Variable:** `Survived`
- **Key Predictors:** All available features after preprocessing and engineering
- **Output Format:** CSV with `PassengerId` and `Survived` (0/1)

#### Goal DM3: Model Family Comparison
- **Business Objective:** BQ3 — Achievable accuracy ceiling
- **Technical Description:** Train at least 4 model families (logistic regression, random forest, gradient boosting, SVM) with hyperparameter tuning. Compare cross-validated accuracy distributions. Identify whether more complex models yield meaningful gains over simpler ones.
- **Target Variable:** `Survived`
- **Key Predictors:** Standardized feature set across all models
- **Output Format:** Comparison table (model, mean CV accuracy, std, best hyperparameters)

#### Goal DM4: Feature Engineering Ablation
- **Business Objective:** BQ4 — Highest-value feature engineering
- **Technical Description:** Using the best model family from DM3, measure accuracy with and without each engineered feature (Title, FamilySize, IsAlone, Deck, FareBin, AgeBin). Quantify the marginal contribution of each.
- **Target Variable:** `Survived`
- **Key Predictors:** Base features vs. base + each engineered feature
- **Output Format:** Ablation table (feature added, accuracy delta, p-value from paired CV test)

### Baseline Definition
- **Current Approach:** Gender-only model (`gender_submission.csv`) — predicts all females survive, all males perish
- **Baseline Performance:** ~76.5% accuracy on Kaggle test set (76.555% exact)
- **How Baseline Was Established:** Provided by Kaggle as `gender_submission.csv`; accuracy confirmed as a well-known benchmark

### Evaluation Methodology
- **Validation Strategy:** Stratified 5-fold cross-validation on training set (preserves class balance ~38% survived)
- **Test Period:** Kaggle holdout test set (418 passengers) — ground truth not available locally
- **Evaluation Frequency:** After each model iteration; Kaggle submission for final candidates only (max 10/day)

## Scope & Constraints

### In Scope
- Binary classification of passenger survival using train.csv features
- Feature engineering from existing columns (Name, Cabin, Ticket parsing)
- Model selection across standard ML families (logistic regression, tree ensembles, SVM)
- Hyperparameter tuning via grid/random search with cross-validation
- Feature importance and ablation analysis
- Kaggle submission generation

### Out of Scope
- Deep learning / neural network approaches (dataset too small to justify)
- External data augmentation (Kaggle rules; fixed dataset constraint)
- Real-time serving or API deployment (one-time submission)
- Survival probability calibration (Kaggle evaluates binary labels only)
- Ensemble stacking of 5+ models (diminishing returns vs. time investment)

### Known Data Limitations
- **Age:** ~20% missing — requires imputation; imputation quality directly affects model performance
- **Cabin:** ~77% missing — too sparse for direct use; can extract deck letter or binary has_cabin indicator
- **Embarked:** 2 missing values — trivial to impute (mode = 'S')
- **Small sample size:** 891 training rows limits model complexity and statistical power of comparisons
- **No ground truth for test set:** Cannot compute test metrics locally; must submit to Kaggle

### Performance Requirements
- **Inference Latency:** Not applicable — batch prediction for 418 rows
- **Retraining Frequency:** Not applicable — one-time competition
- **Data Freshness:** Not applicable — static historical dataset
