## Requirements, Assumptions & Constraints

### Requirements
- **Target Group:** Kaggle leaderboard (automated scoring); secondary: data science team for methodology reference
- **Schedule:** 2-week target (2026-03-30 to 2026-04-13)
- **Accuracy:** >78% minimum (above gender baseline); >80% target (competitive threshold)
- **Comprehensibility:** Feature importance analysis required; model interpretability is a secondary goal
- **Deployability:** CSV submission to Kaggle; no production deployment needed
- **Security & Privacy:** No PII concerns — dataset is public domain, historical (1912). No GDPR applies.
- **Reporting:** Final model card with experiment results; CRISP-DM documentation trail

### Assumptions
| # | Assumption | Category | Impact if Wrong |
|---|-----------|----------|-----------------|
| 1 | Training and test sets are drawn from the same population (same ship, same event) | Data Quality | Low risk — both sets are from the same passenger manifest |
| 2 | The gender baseline (~76.5%) is a reasonable lower bound for any model | Model | If wrong, need to recalibrate success criteria |
| 3 | Missing Cabin data is not random (correlates with class/survival) | Data Quality | Naively dropping Cabin loses a potentially strong signal; imputation or proxy features needed |
| 4 | Age missingness can be reasonably imputed from title/class/sibsp/parch | Data Quality | Poor imputation would add noise; need to validate imputation quality |
| 5 | No data leakage exists in the provided train/test split | Data Quality | If test data leaked into training, Kaggle scores would be misleadingly high |
| 6 | scikit-learn and standard Python libraries are sufficient for competitive accuracy | Technical | If wrong, may need XGBoost/LightGBM — easy to add |

### Constraints
| # | Constraint | Type | Mitigation |
|---|-----------|------|------------|
| 1 | Fixed dataset — cannot collect additional features or rows | Data Access | Focus on feature engineering from existing columns |
| 2 | No ground truth for test set — can only evaluate via Kaggle submission | Data Access | Use cross-validation on training set for development; submit sparingly (10/day limit) |
| 3 | Small dataset (891 training rows) limits model complexity | Data | Prefer simpler models; use cross-validation to avoid overfitting |
| 4 | 2-week timeline | Timeline | Prioritize proven approaches (logistic regression, random forest, gradient boosting) over experimental methods |

## Risks & Contingencies

| # | Risk | Category | Likelihood | Impact | Contingency Plan |
|---|------|----------|------------|--------|------------------|
| 1 | Overfitting due to small dataset | Technical | High | Medium | Use k-fold cross-validation (k=5 or 10); regularization; ensemble methods |
| 2 | Feature engineering yields diminishing returns | Technical | Medium | Low | Set a time-box (3 days max); focus on top-5 known features (sex, pclass, age, fare, family size) |
| 3 | Cabin missingness (~77%) makes it unusable | Data | Medium | Low | Extract deck letter where available; create binary has_cabin feature; accept partial signal |
| 4 | Age imputation introduces bias | Data | Medium | Medium | Compare multiple imputation strategies (median, group-based, model-based); validate via CV |
| 5 | Cross-validation score doesn't match Kaggle score | Technical | Medium | Low | Expected due to different data splits; focus on CV stability rather than single-point estimates |
| 6 | Scope creep — spending too long on marginal improvements | Organizational | Medium | Low | Define "done" as >80% accuracy or 2-week deadline, whichever comes first |

## Terminology

### Business Glossary
| Term | Definition | Example |
|------|-----------|---------|
| Survived | Binary outcome variable: 1 = passenger survived, 0 = deceased | Survived=1 for a 1st-class female passenger |
| Pclass | Passenger ticket class as a proxy for socio-economic status | 1 = Upper, 2 = Middle, 3 = Lower |
| SibSp | Number of siblings or spouses aboard | SibSp=1 means one sibling or spouse on the ship |
| Parch | Number of parents or children aboard | Parch=2 means two parents or children on the ship |
| Embarked | Port of embarkation | C = Cherbourg, Q = Queenstown, S = Southampton |
| Fare | Passenger ticket price in pre-1912 British pounds | Fare=71.28 for a 1st-class ticket |

### Data Mining Glossary
| Term | Definition | Business Context Example |
|------|-----------|------------------------|
| Binary classification | Predicting one of two possible outcomes | Survived (1) vs. Deceased (0) |
| Accuracy | Fraction of correct predictions out of total predictions | 80% accuracy = 334/418 correct test predictions |
| Cross-validation | Splitting training data into k folds to estimate model performance | 5-fold CV on 891 training rows |
| Feature engineering | Creating new predictive variables from existing data | Extracting "Title" (Mr, Mrs, Miss) from Name field |
| Imputation | Filling in missing values with estimated values | Replacing missing Age with median age per title group |
| Ensemble | Combining multiple models to improve prediction | Random Forest = ensemble of decision trees |
| Overfitting | Model memorizes training data and performs poorly on new data | High training accuracy but low CV/Kaggle accuracy |
| Baseline model | Simplest reasonable model used as a performance floor | Gender-only model: all females survive (~76.5%) |
